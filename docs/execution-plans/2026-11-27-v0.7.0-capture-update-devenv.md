# 实施计划：随手记即时保存、更新后台化与开发环境隔离

- 状态：已发布 v0.7.0（2026-11-28）；剩余实机手工验证与真实库回填
- 创建日期：2026-11-27
- 最后更新：2026-11-27
- 负责人：AbelTomato / AI 结对

## 目标

让随手记保存不再等待网页抓取、不再把主窗口带到前台；把检查更新变成后台常驻进程的静默周期任务，发现新版本时通过系统通知与右下角非阻塞提示告知；为历史纯链接记录提供一次性回填脚本；让生产与开发两个进程可以在同一台机器上长期共存。

## 背景与现状

### 已确认的产品决策

1. 随手记采用 A 方案：立即入库 + 「已保存」提示，不自动跳转主窗口。
2. 检查更新每 4 小时一次，启动后延迟首查；应用按后台常驻进程定位。
3. 主窗口隐藏时保留提示能力：第一版做 Windows 系统通知，同时保留右下角小胶囊。
4. 纯链接记录：写入时补全，查询参数最多 3 个（过滤跟踪参数），不做展示层兜底。
5. 历史记录：跑一次性回填脚本，而不是改展示逻辑。
6. 开发/生产隔离：同意独立 identifier、独立凭据命名空间、开发禁用更新。

### 仍然存在的问题

1. **保存仍在等抓取。** `capture_clipboard_content` 是 `async`，先 `await fetch_web_metadata` 再入库，最坏 5 秒，按钮一直显示「保存中…」。
2. **自动检查依赖前端定时器。** `UpdateToast` 用 `window.setTimeout` 在挂载 8 秒后检查一次，之后再无周期检查。主窗口隐藏后 WebView 定时器会被节流甚至挂起，几小时一次的检查并不可靠。
3. **隐藏时没有任何提示。** `UpdateToast` 只在主窗口 DOM 内，窗口隐藏即不可见；`platform::show_notification` 已有能力但未接入更新流程。
4. **历史链接记录不可辨识。** 旧记录 `title` 与 `summary` 为空，列表回退链落到 `source`，全部显示 `quick_capture`。
5. **双进程冲突。** 详见下文「第四部分」。

## 范围

### 包含

- 随手记改为同步入库 + Rust 后台抓取回填，带条件更新与并发上限。
- 检查更新改为 Rust 周期触发，前端负责状态与下载安装；隐藏时发系统通知。
- 新增历史链接记录回填脚本（默认 dry-run，显式 `--apply` 才写库）。
- 开发环境隔离：独立 identifier、产品名、全局快捷键、凭据命名空间，开发构建禁用更新。
- 全局快捷键注册失败不再终止启动。
- 文档与开发日志同步。

### 不包含

- 数据库 schema 变更（不新增迁移）。
- 独立的第三个「更新提示窗口」。
- 展示层对历史空记录的兜底（由回填脚本解决）。
- 更新通知的点击跳转与操作按钮（Windows toast 回调留到后续）。
- 单实例插件（避免 `tauri dev` 热重启被残留进程挡住）。
- 历史开发数据的自动迁移。

## 实施步骤

### 第一部分：随手记即时保存 + 后台补全

1. [x] **抽出链接标签逻辑。** 把 `application/captures.rs` 里的 `link_labels`、`site_label`、`location_hint`、`query_hint`、`is_tracking_key`、`percent_decode` 等纯函数移到 `infrastructure/link_label.rs`，对外暴露 `LinkLabels { title, summary }` 与 `labels_from_url`；保留 `labels_with_metadata` 供抓取成功时使用。这样回填脚本可以复用同一套规则，避免两处逻辑漂移。
2. [x] **数据层增加条件更新。** `CaptureRepository::update_link_metadata` 执行：
       `UPDATE captures SET title = ?, summary = ?, url = ? WHERE id = ? AND title IS ? AND summary IS ?`。
       `IS` 提供 NULL 安全比较，保证用户已经改过标题或摘要时后台不覆盖；**不更新 `updated_at`**，避免回填或补全把记录顶到列表顶部。
3. [x] **入库与抓取解耦。** `capture_clipboard_content` 改为同步函数，链接类直接用 `labels_from_url` 生成标题和摘要后入库，返回 `Captured { capture, pending_link: Option<Url> }`。
4. [x] **命令层派发后台任务。** `capture_from_clipboard` 拿到 `pending_link` 后 `tauri::async_runtime::spawn` 一个补全任务，立即返回记录；任务用 `tokio::sync::Semaphore` 限制最多 2 个并发抓取。
5. [x] **补全任务。** 抓取成功 → 计算新标签 → 调条件更新 → 变更成功时 `emit("capture-enriched", id)`。抓取失败、超时、404 一律静默返回，保留兜底值。
6. [x] **前端刷新。** `CapturesPage` 监听 `capture-enriched`：若当前列表包含该 id 且不在搜索态，刷新首屏；`AppShell` 无需额外处理角标。事件在主窗口隐藏时发出，前端下次打开自然拿到最新数据。

### 第二部分：检查更新后台化

7. [x] **Rust 周期触发器。** 新增 `application/updater.rs`：`start_checker(app)` 先 `sleep(60s)`，之后每 4 小时 `emit("update-check-due", ())`。不做网络请求，只负责「到点提醒」。在 `lib.rs` 的 `setup` 里注册。
8. [x] **前端接住周期事件。** `UpdateToast` 删除 8 秒 `setTimeout`，改为监听 `update-check-due` → `runCheck(false)`；保留 `check-updates-requested` → `runCheck(true)`。这样「何时查」在 Rust，「怎么查、怎么展示」仍在一处。
9. [x] **同版本不重复打扰。** 增加 `tomatodesk:notified-update-version`：后台检查发现同一版本且已通知过时，不再发系统通知；若当前是「稍后」收起态，也不再自动展开卡片。
10. [x] **隐藏时发系统通知。** `runCheck(false)` 发现新版本后读取 `getCurrentWindow().isVisible()`：可见 → 正常显示右下角卡片；不可见 → 调用新增命令 `notify_update_available(version)`，由 Rust 走 `platform::show_notification` 发通知，正文提示「打开 TomatoDesk 即可更新」。
11. [x] **保留后续入口。** 「稍后」继续收起为右下角胶囊「新版本 vX 可用 · 查看」；托盘的「检查更新」始终保持可用，点击时先 `show_main_window` 再触发手动检查，作为通知失败时的兜底。
12. [x] **开发构建不检查。** `runCheck` 在 `import.meta.env.DEV` 下直接返回；手动触发时在卡片里显示「开发构建不检查更新」，不发网络请求。

### 第三部分：历史链接记录回填脚本

13. [x] **可行性结论：可以做。** 前提是先把链接标签逻辑抽到 `infrastructure`（步骤 1），并给 `Database` 加 `busy_timeout`，否则脚本在应用运行时打开同一个 SQLite 会直接报锁错误。
14. [x] **新增 bin。** `src-tauri/src/bin/backfill_capture_labels.rs`，通过 `tomatodesk_lib` 复用 `Database` 与 `labels_from_url`。
15. [x] **参数。**
    - `--db <path>`：显式数据库路径；
    - `--dev`：使用 `com.tomatodesk.app.dev` 的数据目录；
    - `--apply`：真正写库；缺省为 dry-run，只打印将要发生的变更；
    - `--fetch`：额外联网抓取标题和描述，默认只按 URL 推导；
    - `--limit <n>`：本次最多处理多少条。
16. [x] **筛选条件。** `kind = 'link' AND url IS NOT NULL AND (title IS NULL OR trim(title) = '' OR summary IS NULL OR trim(summary) = '')`。空标题和空摘要分开判断，只补缺失的一侧。
17. [x] **写入规则。** 逐条短事务更新，只改 `title`、`summary`、`url`，**不动 `note`、`body`、`archived_at`、`created_at`、`updated_at`**。`captures_fts` 已有 `AFTER UPDATE OF title, summary` 触发器，搜索索引会自动同步，无需手动 rebuild。
18. [x] **安全兜底。** `--apply` 前先 `VACUUM INTO backup/tomatodesk-before-backfill-<时间戳>.sqlite3`；执行中打印进度；结束输出「扫描 / 补全 / 跳过 / 失败」统计。脚本运行前提示先退出 TomatoDesk，避免写锁竞争。

### 第四部分：开发 / 生产双进程隔离

19. [x] **热键注册容错。** `platform::setup` 中全局快捷键注册失败只记录警告，不再向上抛错。这是「后启动进程被杀」的直接原因：注册冲突让 `setup` 返回 `Err`，应用初始化失败后自行退出，并不是系统杀进程。
20. [x] **区分热键。** debug 构建使用 `Ctrl + Alt + Shift + Space`，release 保持 `Ctrl + Shift + Space`。全局快捷键属于操作系统级命名空间，不随 identifier 隔离，必须单独区分。
21. [x] **开发配置。** 新增 `src-tauri/tauri.dev.conf.json`，覆盖 `productName: "TomatoDesk Dev"`、`identifier: "com.tomatodesk.app.dev"`。identifier 变化会同时带来独立数据目录、独立 WebView 存储与独立通知身份。
22. [x] **凭据命名空间。** `infrastructure/secrets` 的 `SERVICE` 在 debug 构建下改为 `TomatoDesk Dev`，避免开发进程覆盖或删除生产 Token。
23. [x] **开发禁用更新。** `lib.rs` 在 debug 构建下不注册 updater 插件；前端同步跳过检查。避免开发进程把生产安装覆盖掉。
24. [x] **启动脚本。** `package.json` 增加 `"tauri:dev": "tauri dev --config src-tauri/tauri.dev.conf.json"`，让「同时跑生产 + 开发」成为默认路径，而不是靠人记参数。

### 手工验证

1. **保存不跳转**：在主窗口隐藏、焦点在浏览器的状态下按 `Ctrl+Shift+Space` 保存一条链接。预期：随手记窗口出现约 1 秒「已保存」后消失，主窗口不弹出，浏览器焦点不丢。
2. **保存不等待**：粘贴一个响应很慢的链接。预期：保存按钮立刻恢复并显示「已保存」，不等抓取。
3. **后台补全**：上一步保存后打开主窗口。预期：记录先显示站点 + 路径，几秒后自动替换成网页标题。
4. **用户编辑不被覆盖**：保存链接后立刻把标题改成自定义值，等待抓取完成。预期：标题保持用户输入。
5. **隐藏时通知**：把主窗口收到托盘，等待周期检查或手动触发到点事件。预期：出现 Windows 通知；打开主窗口后能看到右下角卡片或胶囊。
6. **小胶囊**：点「稍后」。预期：卡片收成右下角小胶囊，点「查看」能重新展开，下载与安装按钮可用。
7. **同版本不重复**：同一版本再次到点检查。预期：不再弹系统通知，不自动展开卡片。
8. **回填脚本**：先 `--dry-run` 查看变更清单，再 `--apply`。预期：旧链接标题从 `quick_capture` 变为 `站点 / 路径`；列表时间顺序不变；搜索结果能命中新标题。
9. **双进程共存**：生产版常驻运行，执行 `pnpm tauri:dev`。预期：开发进程正常启动，两个托盘图标并存；生产 `Ctrl+Shift+Space` 与开发 `Ctrl+Alt+Shift+Space` 各自生效；两边数据与 Token 互不影响。
10. **热键被占用**：用其他软件占用生产热键后启动。预期：应用仍能启动，托盘可用，仅热键失效。

## 风险与回滚

| 风险                                         | 影响                        | 应对                                                                     |
| -------------------------------------------- | --------------------------- | ------------------------------------------------------------------------ |
| 隐藏窗口的 WebView 事件被节流                | 周期检查延迟，通知不及时    | 托盘「检查更新」作为兜底；若实测明显延迟，再升级为 Rust 侧直接检查版本   |
| 条件更新误判                                 | 用户编辑被覆盖              | 比较 `title`/`summary` 原值，`IS` 支持 NULL；任何不一致都放弃写入        |
| 回填改变列表排序                             | 旧记录跳到顶部              | 明确不更新 `updated_at`，写库前 dry-run 复核                             |
| 脚本与运行中的应用争用写锁                   | 脚本报 `database is locked` | 设置 `busy_timeout`，文档提示先退出应用                                  |
| 换 identifier 后旧开发数据不可见             | 开发环境像「清空」了        | 接受重新建库；如需保留，手工复制 `%APPDATA%\com.tomatodesk.app` 到新目录 |
| 系统通知在未正确注册 AppUserModelID 时不显示 | 隐藏时无提示                | 托盘菜单与下次打开主窗口的卡片兜底；不作为唯一通道                       |
| 开发环境忘记带配置启动                       | 又回到共享数据、热键冲突    | 固定 `tauri:dev` 脚本；README 与开发文档写明入口                         |

**回滚**：本次不涉及数据库迁移，回滚只需 `git revert` 对应提交。回填脚本的写库前备份可直接替换回原库。
