## 目标

解决 V0.2.0 验收暴露的三个问题，并把视觉体系对齐到博客项目 `AbelTomato.github.io`：先把列表与正文拆成两级加载（P0），再把产品主体从「事件汇入 Inbox」改为「按仓库组织的工作站」（P1），最后按博客的设计语言统一视觉（P2）。

## 背景与现状

V0.2.0 验收结论：同步 Octop 后 Inbox 一次涌入两千余条内容且加载缓慢；产品形态偏向 todo 式单一收件箱；UI 无功能缺陷但缺少自有设计细节。

代码侧根因（已核对）：

- `application/github.rs` 以 `state=all` 分页拉取仓库全部 Issue/PR，并把 `issue.body` 全量写入 `items.summary`。
- 同一条正文在 `items.summary` 与 `github_events.payload_json` 中各存一份。
- `ItemRepository::list()` 无分页、无字段裁剪，返回全部行的全部列。
- `Inbox.tsx` 用 `listItems()` 一次性取回全部数据，在 JS 里做筛选、排序、计数，详情面板从已加载数组中取。
- `ItemKind` 含 `github`，GitHub 数据与个人收集共用 `items` + `pending/processed/archived` 三态，是形态偏移的结构性原因。
- 视觉层使用 `rounded-lg + border + p-5` 卡片、`rounded-full` 彩色 pill 与 `uppercase tracking-[0.18em]` 眉标，与博客的克制风格不一致。

## 范围

### 包含

- 列表/详情两级加载、键集分页、状态计数下沉 SQL。
- 正文与摘要分离，去掉重复存储，FTS 覆盖正文。
- 仓库工作区信息架构与数据模型（仓库元信息、README 摘要、自定义描述、线程表、我的条目）。
- 视觉基座（token + 字体 + 主题）与基础组件收敛，对齐博客规范。

### 不包含

- 评论、Review 正文、Commit 流的完整同步。
- 多账号、云端同步、移动端。
- 博客与桌面端共享组件包（只共享规范，不抽 monorepo）。
- 现有 `items.kind` CHECK 约束的重建（保留 `github` 值作为技术债）。

### 阶段一：加载性能（P0）

**1.1 正文与摘要分离**

- 目标：正文只存一份，列表不再携带全文。
- 范围：迁移 `0002_item_body.sql`；`items` 增 `body`，现有 `summary` 迁入并截断 200 字；重建 `items_fts`（含 `body`）与三个触发器；补 `(updated_at, id)` 索引。
- 产出：迁移文件、`database.rs` 注册、FTS 重建后的行数校验结果。

**1.2 分页列表与计数接口**

- 目标：列表只传索引字段，支持翻页。
- 范围：新增 `ItemSummary` DTO、`list_items_page({status, kind, cursor, limit})`（键集分页，默认 50）、`count_items_by_status`；`search_items` 返回摘要行并限 100 条。
- 产出：Rust 命令 + `api.ts` 方法 + 对应单元测试（分页边界、游标失效、计数一致性）。

**1.3 详情按需加载**

- 目标：点开才取正文。
- 范围：新增 `get_item_body(id)`，优先读本地 `body`，为空时对 link 回源、对 GitHub 返回本地缓存。
- 产出：命令 + 前端详情面板的加载骨架与失败态。

**1.4 同步写入收敛**

- 目标：同步不再制造两份正文，且默认只同步活跃内容。
- 范围：`sync_repo_contents` 写 `summary` 摘要 + `body` 全文、`payload_json` 去正文；单仓库合并为一个事务；默认 `state=open` + `since=last_synced_at`，关闭项改为显式「加载历史」。
- 产出：同步服务改造 + 二次同步 `notModified` 验证记录。

**1.5 Inbox 改造**

- 目标：首屏只渲染 50 条，滚动增量加载。
- 范围：`Inbox.tsx` 拆 `items: ItemSummary[]` 与 `selectedItem: Item | null`；`IntersectionObserver` 触发加载更多；筛选排序交给后端；侧栏计数用接口。
- 产出：改造后的 Inbox，含加载更多、空态、错误态、骨架屏。

### 与计划的偏差（已确认按此执行）

1. **`notModified` 语义改为「本次没有新增条目」**。`since` 每次同步都会前进，同一 URL 的 ETag 不可能命中，继续发条件请求只会让「连续同步两次第二次 notModified」这条验收永远不成立。因此同步请求不再发 `If-None-Match`，`not_modified = imported_count == 0`。`github_repos.etag` 列保留但不再写入，作为后续可能复用的遗留字段。
2. **索引比计划多两个**。只建 `(updated_at, id)` 无法覆盖按状态/类型过滤后的排序，补了 `(status, updated_at, id)` 与 `(kind, updated_at, id)`。
3. **游标格式**为 `排序值|id`，对前端不透明；解析失败按 `validation` 错误返回，前端提示重新加载。
4. **`search_items` 仍走 FTS 但只返回摘要行**，最多 100 条且不分页；搜索模式下的状态/类型筛选在前端补做（结果集有界）。
5. **`items.kind` 仍含 `github`**，按计划保留为技术债，等阶段二 `0003` 一并处理。

## 风险与回滚

- 风险：`0003` 删除旧 GitHub 条目不可逆；缓解为迁移前自动备份数据库到 `userData/backup/`，并在迁移后提示重新同步。
- 风险：README 渲染引入 XSS 面；缓解为首版只展示纯文本摘要，不渲染 HTML。
- 风险：`backdrop-filter` 在 WebView2 上开销高，大面积使用会导致滚动掉帧；缓解为只用于头部、浮层、弹窗，列表与面板用不透明 `bg-card`。
- 风险：霞鹜文楷全量打包会让安装包明显变大；缓解为先测体积，超过 15 MB 则改用精简字重或系统中文回落。
- 风险：`since` 增量可能漏掉编辑历史；缓解为保留「全量重同步」入口。
- 回滚：迁移按版本号顺序执行，回滚需恢复备份；阶段零与阶段一、二相互独立，可单独回退。
