- 状态：已完成（阶段零、一、二、三均已落地；阶段三代码未提交）

## 目标

解决 V0.2.0 验收暴露的三个问题，并把视觉体系对齐到博客项目 `AbelTomato.github.io`：先把列表与正文拆成两级加载（P0），再把产品主体从「事件汇入 Inbox」改为「按仓库组织的工作站」（P1），最后按博客的设计语言统一视觉（P2）。

## 背景与现状

V0.2.0 验收结论：同步 Octop 后 Inbox 一次涌入两千余条内容且加载缓慢；产品形态偏向 todo 式单一收件箱；UI 无功能缺陷但缺少自有设计细节。

代码侧根因（已核对）：

- `application/github.rs` 以 `state=all` 分页拉取仓库全部 Issue/PR，并把 `issue.body` 全量写入 `items.summary`。
- 同一条正文在 `items.summary` 与 `github_events.payload_json` 中各存一份。
- `ItemRepository::list()` 无分页、无字段裁剪，返回全部行的全部列。
- `Inbox.tsx` 用 `listItems()` 一次性取回全部数据，在 JS 里做筛选、排序、计数，详情面板从已加载数组中取。
- `ItemKind` 含 `github`，GitHub 数据与个人收集共用 `items` + `pending/processed/archived` 三态，是形态偏移的结构性原因。
- 视觉层使用 `rounded-lg + border + p-5` 卡片、`rounded-full` 彩色 pill 与 `uppercase tracking-[0.18em]` 眉标，与博客的克制风格不一致。

## 范围

### 包含

- 列表/详情两级加载、键集分页、状态计数下沉 SQL。
- 正文与摘要分离，去掉重复存储，FTS 覆盖正文。
- 仓库工作区信息架构与数据模型（仓库元信息、README 摘要、自定义描述、线程表、我的条目）。
- 视觉基座（token + 字体 + 主题）与基础组件收敛，对齐博客规范。

### 不包含

- 评论、Review 正文、Commit 流的完整同步。
- 多账号、云端同步、移动端。
- 博客与桌面端共享组件包（只共享规范，不抽 monorepo）。
- 现有 `items.kind` CHECK 约束的重建（保留 `github` 值作为技术债）。

### 阶段一：加载性能（P0）

**1.1 正文与摘要分离**

- 目标：正文只存一份，列表不再携带全文。
- 范围：迁移 `0002_item_body.sql`；`items` 增 `body`，现有 `summary` 迁入并截断 200 字；重建 `items_fts`（含 `body`）与三个触发器；补 `(updated_at, id)` 索引。

- 目标：列表只传索引字段，支持翻页。

- 产出：Rust 命令 + `api.ts` 方法 + 对应单元测试（分页边界、游标失效、计数一致性）。

**1.3 详情按需加载**

- 目标：点开才取正文。
- 范围：新增 `get_item_body(id)`，优先读本地 `body`，为空时对 link 回源、对 GitHub 返回本地缓存。
- 产出：命令 + 前端详情面板的加载骨架与失败态。

**1.4 同步写入收敛**

- 目标：同步不再制造两份正文，且默认只同步活跃内容。

**1.5 Inbox 改造**

- 目标：首屏只渲染 50 条，滚动增量加载。

## 阶段一实施结果（2026-11-25）

### 落地内容

- **2.1 数据模型**：`migrations/0003_repo_workspace.sql`。`items` 增 `repo_id`（`ON DELETE SET NULL`）与 `(repo_id, updated_at, id)` 索引；`github_repos` 扩 description / homepage / language / stars / forks / open_issues / default_branch / pushed_at / is_archived / is_private / readme_text / readme_summary / readme_synced_at / custom_description / custom_note / meta_synced_at；新建 `github_threads`（`UNIQUE(repo_id, kind, number)`，含四个关系位与 `state ∈ open/draft/merged/closed`）与 `github_releases`（`UNIQUE(repo_id, tag_name)`）；`DELETE FROM items WHERE kind='github'` 并 `DROP TABLE github_events`。`database.rs` 注册版本 3，并在「已有数据的库」执行迁移前用 `VACUUM INTO` 备份到 `<数据目录>/backup/`（失败回落 `fs::copy`），把备份路径与目标版本记进 `MigrationNotice`。
- **2.2 GitHub 客户端**：`infrastructure/github` 新增 `viewer()`、`repository()`、`readme()`（`Accept: vnd.github.raw`，404 返回 `None`）、`pulls()`（`sort=updated&direction=desc`，遇到早于 `since` 的条目即停止翻页）、`reviews()`；`issues()` 增 `user` / `assignees` / `comments` / `closed_at`；关系判定 `infer_relations` 从 `user.login`、`assignees`、`requested_reviewers`、`reviews` 推导四个布尔位。
- **2.3 仓库页**：命令 `list_repos`、`get_repo`、`update_repo_meta`、`list_repo_threads`、`get_thread`、`list_repo_releases`；`src/features/repos/ReposPage.tsx`（仓库列表：描述、语言、Star、PR/Issue/评审/Release/我的条目计数、最近同步）与 `RepoDetail.tsx`（概览 + 六个标签页：概览 / Pull Requests / Issues / 评审 / Release / 我的条目）；概览的自定义描述与备注行内编辑、失焦保存；线程行展示状态、编号、标题、关系、增删行与相对时间，选中后按需加载正文；Release 支持展开全文；「我的条目」可新增笔记并改状态。
- **2.4 导航收敛**：`src/app/AppShell.tsx` 承接主导航「收集 / 仓库 / 搜索 / 设置」、快速收集入口、待处理角标与更新横幅；`Inbox.tsx` 回归个人收集（移除 GitHub 类型筛选、同步入口、导出与导航）；新增 `SearchPage.tsx`（全局搜索 + 正文按需加载）与 `SettingsPage.tsx`（Token、仓库增删与同步、导出、同步记录、关于）；`GithubPanel.tsx` 删除。

### 与计划的偏差（已确认按此执行）

1. **`notModified` 语义改为「本次没有新增条目」**。`since` 每次同步都会前进，同一 URL 的 ETag 不可能命中，继续发条件请求只会让「连续同步两次第二次 notModified」这条验收永远不成立。因此同步请求不再发 `If-None-Match`，`not_modified = imported_count == 0`。`github_repos.etag` 列保留但不再写入，作为后续可能复用的遗留字段。
2. **索引比计划多两个**。只建 `(updated_at, id)` 无法覆盖按状态/类型过滤后的排序，补了 `(status, updated_at, id)` 与 `(kind, updated_at, id)`。
3. **游标格式**为 `排序值|id`，对前端不透明；解析失败按 `validation` 错误返回，前端提示重新加载。
4. **`search_items` 仍走 FTS 但只返回摘要行**，最多 100 条且不分页；搜索模式下的状态/类型筛选在前端补做（结果集有界）。
5. **`items.kind` 仍含 `github`**，按计划保留为技术债，等阶段二 `0003` 一并处理。

### 与计划的偏差（已确认按此执行）

1. **`sync_repo(scope)` 沿用 `sync_github_repo` 名称**。前端两处入口都调它，为一个名字改 IPC 没有收益。
2. **多一个 IPC `list_repo_releases`**。计划里的六个命令没有覆盖 Release 标签页的数据来源，塞进 `get_repo` 会让页面首屏带上全部发布说明正文。
3. **多一张表 `github_releases`**。Release 没有编号，无法满足 `github_threads` 的 `UNIQUE(repo_id, kind, number)`。
4. **关系用四个布尔位而非单一枚举**。四种关系可以同时成立；主标签（我发起 > 待我评审 > 我评审过 > 指派给我）在读取时派生。评审标签页因此拆成「待我评审 / 我评审过」两个子筛选，正好各对应一个布尔位。
5. **增量同步的 `state` 从 `open` 改为「有游标时 `all`」**。`since` 已经把载荷压到最近改动，用 `all` 才能把刚关闭的条目改成 `closed`；首次同步没有游标仍只取 `open`，避免一次拉回全部历史。
6. **`pulls` 不支持 `since`**，改为按 `updated` 倒序翻页，遇到早于 `since` 的条目即停止。
7. **`reviewed` 需要额外请求**。每个仓库单次同步最多补查 20 个「不是我作者、也没要求我评审」的 PR；超出部分这一轮关系判定为空，下一轮会补上。
8. **`notModified` 语义改为「本次没有新增或变化的行」**。线程与 Release 的 upsert 都带 `WHERE` 逐列比较，内容没变不写库，返回值直接就是变化行数。
9. **README 请求失败时保留上一次内容**。只有 404（仓库确实没有 README）才清空，避免一次网络抖动把摘要洗掉。
10. **`items.kind` 仍保留 `github` 取值**（CHECK 未重建），但不再产生新行；前端类型筛选已移除该选项。
11. **迁移提示走新命令 `get_migration_notice`**，AppShell 顶部显示一次性横幅并附备份路径，不阻塞任何操作。

### 独立滚动与 PR / Issue 详情页（2026-11-25 补充）

**问题一：左右两栏同步滚动。** 根因不在两栏本身——`ThreadsTab` 的列表与面板各自都有 `overflow-y-auto`，但 `AppShell` 的 `main` 用的是 `min-h-screen`，页面高度随内容增长，两栏的 `flex-1` 永远等于内容高度，滚动条从不出现，最终由文档统一滚动，看起来就是「一起滚」。

**问题二：右侧面板承担了详情页的职责。** 面板原来铺完整正文，正文一长右栏就成了第二份列表。

## 风险与回滚

- 风险：`0003` 删除旧 GitHub 条目不可逆；缓解为迁移前自动备份数据库到 `userData/backup/`，并在迁移后提示重新同步。
- 风险：README 渲染引入 XSS 面；缓解为首版只展示纯文本摘要，不渲染 HTML。
- 风险：`backdrop-filter` 在 WebView2 上开销高，大面积使用会导致滚动掉帧；缓解为只用于头部、浮层、弹窗，列表与面板用不透明 `bg-card`。
- 风险：霞鹜文楷全量打包会让安装包明显变大；缓解为先测体积，超过 15 MB 则改用精简字重或系统中文回落。
- 风险：`since` 增量可能漏掉编辑历史；缓解为保留「全量重同步」入口。
- 回滚：迁移按版本号顺序执行，回滚需恢复备份；阶段零与阶段一、二相互独立，可单独回退。
