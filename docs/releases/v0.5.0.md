# TomatoDesk v0.5.0

这个版本把邮箱接进了收件箱：最多 5 个 IMAP 账户，用授权码登录，后台每 10 分钟自动收一次信。邮件不再需要另开客户端盯，而是和 GitHub 通知一样落进收件箱，由你决定忽略还是转成待办。

## 主要变化

- **邮箱账户**：设置页新增「邮箱账户」区块，最多 5 个账户。填地址、授权码、服务器、端口、加密方式（SSL/TLS 或 STARTTLS）与文件夹；QQ、163、Gmail、iCloud 会按域名预填服务器与端口。「测试连接」立即验证并回显邮箱里的邮件封数与 `UIDVALIDITY`，不保存任何东西。
- **改配置不用重填授权码**：编辑时地址与服务器锁住（要换服务器请删掉重建），授权码留空表示沿用已保存的值，改端口或加密方式不必再找一次授权码。
- **自动同步**：保存账户后立刻同步一次，之后每 10 分钟一轮。首次取最近 14 天内最新的 100 封，之后按 UID 增量拉取，单账户单轮最多 100 封、60 秒预算；整轮 5 分钟，没跑完的账户留到下一轮继续，不会漏也不会重复。
- **邮件进收件箱**：邮件标为「邮件」类型，展示主题、发件人、时间与正文。正文优先取纯文本，只有 HTML 时转成纯文本（丢弃脚本、样式与追踪像素，不加载远程图片）；GBK / GB18030 编码的旧邮件能正常解码；附件只列出文件名，不下载。
- **只读收信**：同步用只读方式打开邮箱并 `BODY.PEEK` 取信，不会把服务器上的邮件标成已读。在 TomatoDesk 里点开一封邮件，网页邮箱里它仍然是未读。
- **多账户互不牵连**：一个账户授权码失效或断网，只影响它自己——错误显示在来源栏和设置页，60 分钟后才重试，不会每轮反复撞服务商风控；其他账户照常同步。
- **凭据不落库**：授权码只写进 Windows 凭据管理器，按账户分开存；不出现在数据库、IPC 返回值、日志和消息负载里。删除账户只清配置与凭据，历史邮件保留在收件箱。

## 升级须知

- **不需要数据库迁移**：本版本没有新增迁移，数据库版本仍是 v8，启动时不会改动结构；GitHub 通知、待办与随手记不受影响。
- 邮件账户需要手动添加一次；没有配置账户时后台不会发起任何网络请求。
- 已经是 0.4.0 的用户会通过应用内更新收到本版本，无需手动下载。

## 安装

1. 下载 `TomatoDesk_0.5.0_x64-setup.exe`。
2. 使用同目录下的 `.exe.sha256` 校验安装包完整性。
3. 直接运行安装程序覆盖安装，无需先卸载。

安装包面向 Windows x64，需要 WebView2 运行时（Windows 10/11 通常已预装）。

## 发布资产

- `TomatoDesk_0.5.0_x64-setup.exe`：NSIS 安装程序，同时作为更新包。
- `*.exe.sha256`：安装包的 SHA-256 校验值。
- `*.exe.sig`：更新包签名，供应用内更新验签。
- `latest.json`：更新清单，指向被标记为 Latest 的 Release。
- `manifest.json`：构建清单，包含版本、源码提交号与校验值。

## 已知限制

- **不支持 Outlook / Microsoft 365**：两者已关闭基本认证，需要 OAuth2；本版本只支持授权码 / 应用专用密码登录，也不支持 NTLM。
- **只能填授权码**：QQ、163、Gmail 填登录密码会登录失败，需先在邮箱后台开启 IMAP 并生成授权码或应用专用密码。
- **已读不回写服务器**：本地标记已读只代表你看过，不会同步到邮箱；也不支持在应用内回复或发信。
- **不下载附件**：只保留附件名；正文为空但有附件时会写一行「含 N 个附件」的占位说明。
- **只取收件箱**：只订阅 `INBOX`，不拉取其他文件夹；不做按 `References` 的会话聚合。
- **首次窗口有限**：只回溯最近 14 天、最多 100 封，更早的历史邮件不会补拉。
- **超长邮件会截断**：单封最多读取 256 KB、正文 64 K 字符、摘要 200 字，超出部分丢弃。
- 安装包仍未进行代码签名，首次安装时 Windows SmartScreen 可能提示未知发布者；更新包的 minisign 签名只保证更新来源可信，不消除该提示。
- 仅提供 Windows x64 安装包，暂无 macOS/Linux 版本。
